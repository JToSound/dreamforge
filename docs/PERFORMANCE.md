# Performance — measured results (2026-08-24)

> DreamForge is a research and visualization simulator. It does not measure brains, diagnose conditions, predict dreams, infer psychological meaning, or provide medical advice.

All numbers below are **observed wall-clock measurements** from
`scripts/benchmark.py` on the development machine (Windows 11, Python
3.12.10, numpy 2.5.2, single run each — no warmup statistics). They describe
THIS machine only and are not guarantees; rerun the script for your own
hardware.

Reproduce:

```bash
".venv/Scripts/python.exe" scripts/benchmark.py
```

Raw JSON: `exports/_bench_results.json` (regenerated by the script).

## Engine throughput (fixed seed 42)

| ticks | wall s | epochs/s | events emitted | peak traced MB | core hash (first 12) |
|---|---|---|---|---|---|
| 960 (8h demo scale) | ~1.1–1.2 | 795–890 | 3,072 | 11.0 | `38626c6584e5` |
| 9,600 (10× night) | 10.4–11.2 | 857–923 | 30,720 | 100.3 | `66b3e26a04c8` |
| 19,200 (20× night) | 21.3–22.6 | 850–901 | 61,440 | 200.7 | `7cb0b9bafd91` |

Observations (from these runs):

- Throughput is essentially **flat across a 20× size increase**
  (~850–923 epochs/s): cost scales linearly with epochs, no super-linear
  blow-up from the graph or event store.
- Peak memory tracks emitted events (~3.2 events/epoch ≈ 10 KB/epoch traced),
  i.e. linear as designed; the in-memory store keeps every event.
- The bundled 8-hour demo completes in about one second of wall time.

## DQCJ-1 canonical serialization

- ~27,600 quantized canonicalizations/s on a mixed dict payload
  (20 int array + 20 float array quantized to 1e-6 + string), single thread.

## Export/import round trip (layout v2, 3,072 events)

- write_export: ~0.08 s
- import_and_verify with all 22 fail-closed checks: ~0.15 s

Verification cost is roughly 2× export cost and stays sub-second at demo
scale.

## What is NOT measured here

- Multi-night repository scaling beyond stored summaries.
- Networked provider latency (by design offline-tested; real latency depends
  entirely on the endpoint you configure).
- Streamlit UI responsiveness (depends on browser).
- Cold-start/import time of the package itself.

No performance claims are made beyond this table; nothing here implies
clinical, biological, or real-time suitability.
